# Расширения промоакций для CS-Cart

Модуль `ee_first_purchase_verivication` добавляет в CS-Cart и Multi-Vendor три расширения штатных промоакций:

1. Условие **«Первая покупка пользователя»**.
2. Бонус **«Бонусные баллы: целевой процент от подходящих товаров»** для промоакций корзины.
3. Бонус **«Скидка на доставку, %»** для выбранного способа доставки.

Модуль использует штатные механизмы Promotions и, опционально, Reward Points. Он не создает собственных таблиц и не начисляет баллы напрямую.

## Совместимость

- CS-Cart / Multi-Vendor `4.12.1`-`4.21.1` согласно манифесту модуля.
- Редакции: `MULTIVENDOR`, `ULTIMATE`.
- Опциональная интеграция: штатный модуль **Reward Points** (`reward_points`). Условие первой покупки от него не зависит.
- Реализация промоакций, расчет доставки и сохранение заказа проверены по исходному коду CS-Cart Ultimate `4.13.1`.
- Ранее модуль проверен на Multi-Vendor `4.20.1 RU`; совместимые контракты хуков поддерживаются в заявленном диапазоне.
- Языки интерфейса: русский и английский.

> Название каталога и идентификатор `ee_first_purchase_verivication` содержат историческую опечатку. Переименовывать их нельзя: идентификатор используется CS-Cart и существующими установками модуля.

## Возможности

### Первая покупка пользователя

Условие доступно в промоакциях каталога и корзины. Оно выполняется, когда:

- покупатель авторизован;
- у покупателя нет предыдущих заказов;
- незавершенные заказы со статусом `STATUS_INCOMPLETED_ORDER` не учитываются.

Само условие ничего не начисляет и не предоставляет скидку. К нему нужно добавить подходящий штатный бонус промоакции: скидку, бесплатную доставку или другой доступный бонус.

Область проверки истории заказов:

- в CS-Cart Ultimate — текущая витрина;
- в Multi-Vendor — весь маркетплейс.

### Целевой процент бонусных баллов

Функция включается глобально в режиме **«Все витрины» / «Все продавцы»** настройкой **«Использовать начисление бонусных баллов»**. Настройку можно включить только при установленном и активном Reward Points.

Бонус доступен **только в промоакциях корзины**. Он задает итоговый процент начисления Reward Points для подходящих товаров. Промоакции по-прежнему можно создавать для любого количества витрин штатными средствами CS-Cart.

Например, если стандартное начисление составляет 1%, а акция должна начислять 5%, в бонусе указывается `5`. Результат для подходящих товаров составит 5%, а не 6%.

Для выбора товаров используются штатные товарные условия промоакции:

- **Товары**;
- **Категории**;
- **Характеристика**.

Для акции по бренду используется условие **«Характеристика»**: необходимо выбрать характеристику бренда и нужные варианты. Список характеристик и их доступность формирует штатный интерфейс CS-Cart, а модуль только применяет сохраненное условие при расчете баллов.

Другие условия — пользовательская группа, купон, сумма заказа, страна, первая покупка и подобные — определяют применимость промоакции целиком, но не отбирают отдельные товары для повышенного процента.

Правила расчета:

- если нет условий **«Товары»**, **«Категории»** или **«Характеристика»**, процент применяется ко всем товарам корзины;
- если товар подходит под несколько процентных бонусов, применяется наибольший целевой процент;
- процент рассчитывается от цены единицы товара после расчета корзины;
- округление количества баллов выполняется до целого числа;
- для гостей бонус не применяется.

Модуль изменяет расчет баллов в корзине. Сохранение баллов в заказе и их фактическое зачисление выполняет штатный Reward Points. Момент зачисления определяется настройками статусов заказа в CS-Cart, например статусом **«Выполнен»**.

Если Reward Points будет выключен, удален или его файлы станут недоступны после настройки акции, бонус перейдет в безопасный режим и перестанет менять расчет корзины. В панели администратора появится закрепленное предупреждение. Условие первой покупки и остальные бонусы промоакций продолжат работать.

### Процентная скидка на доставку

Бонус доступен только в промоакциях корзины. Администратор выбирает конкретный способ доставки и задает скидку от `1` до `100` процентов. Скидка применяется к рассчитанному CS-Cart тарифу выбранного способа. Например, тариф `600` и скидка `50%` дают итоговую стоимость `300`.

Правила расчета:

- стоимость доставки не опускается ниже `0`;
- другие способы доставки не изменяются;
- при нескольких скидках используется максимальный процент либо сумма процентов с ограничением `100%`;
- при одновременной бесплатной доставке приоритет выбирается в настройках модуля;
- сначала штатный механизм CS-Cart обрабатывает **Priority / Stop other rules**, затем модуль разрешает только оставшиеся конфликты;
- каждый AJAX-пересчет начинается с исходного тарифа, поэтому скидка не накапливается;
- измененный тариф входит в `shipping_cost`, `chosen_shippings` и сохраняется в заказ штатным механизмом CS-Cart.

Настройки конфликтов поддерживают отдельные значения для любого количества витрин.

### Диагностические логи

Предупреждения и ошибки записываются всегда. Для подробной трассировки временно включите глобальную настройку **«Подробное диагностическое логирование»**. Она добавляет события о принятых бонусах, разрешении конфликтов, исходных и итоговых тарифах и стоимости доставки, переданной при создании заказа.

Журнал находится в:

```text
app/addons/ee_first_purchase_verivication/logs/ee_first_purchase_verivication.jsonl
```

Формат — JSON Lines: каждая строка является самостоятельным объектом схемы `ee_first_purchase_verivication.log.v1`. Запись содержит UTC-время, уровень, код и описание события, `request_id`, версии модуля, CS-Cart и PHP, область выполнения, идентификаторы витрины/компании и безопасный контекст расчета.

Контактные данные, адреса, пароли, токены, cookies, сессии, платежные данные и API-ключи заменяются на `[REDACTED]`. Полные корзины, данные покупателя и содержимое платежей не записываются.

Ротация выполняется при достижении `5 МиБ` под эксклюзивной файловой блокировкой. Хранятся активный файл и пять архивов `.jsonl.1`-`.jsonl.5`, где `.1` — самый новый. Каталог защищен от HTTP-доступа правилами Apache/IIS и общим запретом CS-Cart для каталога `app`. Если запись невозможна, в панели администратора появляется предупреждение, а краткое сообщение отправляется в системный PHP error log.

## Установка

1. В панели администратора открыть **Модули → Управление модулями**.
2. Загрузить архив `ee_first_purchase_verivication.zip` и установить модуль.
3. Очистить кеш CS-Cart.
4. Открыть настройки модуля и убедиться, что флажок **«Включить расширения промоакций»** установлен.
5. Для процентного начисления установить и включить штатный Reward Points, затем включить **«Использовать начисление бонусных баллов»**. Для условия первой покупки этот шаг не нужен.

Документация для администратора также доступна на отдельной вкладке **«Документация»** в настройках модуля.

## Настройка

### Бонус для первой покупки

1. Открыть **Маркетинг → Промоакции**.
2. Создать промоакцию каталога или корзины.
3. Добавить условие **«Первая покупка пользователя»**.
4. Добавить нужный штатный бонус промоакции.
5. Задать период действия и сохранить промоакцию.

### Повышенные баллы по категории

1. Создать промоакцию **для корзины**.
2. Добавить условие **«Категории»** и выбрать категории акции.
3. На вкладке бонусов добавить **«Бонусные баллы: целевой процент от подходящих товаров»**.
4. Указать целевой процент, например `5`.

### Повышенные баллы по бренду

1. Создать промоакцию **для корзины**.
2. Добавить условие **«Характеристика»**.
3. Выбрать характеристику **«Бренд»** и варианты брендов.
4. Добавить процентный бонус и указать целевой процент.

### Скидка на способ доставки

1. Создать промоакцию **для корзины**.
2. Добавить условия акции и при необходимости настроить штатные **Приоритет** и **Остановить другие правила**.
3. На вкладке бонусов добавить **«Скидка на доставку, %»**.
4. Выбрать способ доставки и указать процент от `1` до `100`.
5. В настройках модуля выбрать правила для нескольких скидок и сочетания с бесплатной доставкой.

## Ограничения

- Процентный бонус не отображается в промоакциях каталога.
- Скидка на доставку поддерживает только процентный расчет; налоги на доставку отдельно не пересчитываются.
- Поддерживаются только товарные условия `products`, `categories` и `feature`.
- Стандартный процент для всех покупок настраивается в Reward Points; для него отдельная промоакция не нужна.
- Отмененные и другие завершенные заказы считаются предыдущими покупками. Игнорируются только незавершенные заказы CS-Cart.
- Модуль не управляет перечнем характеристик в форме промоакции.
- Правила начисления и списания Reward Points, курс баллов и статусы зачисления настраиваются штатными средствами CS-Cart.
